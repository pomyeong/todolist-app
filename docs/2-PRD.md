## 1. 개요

| 항목 | 내용 |
|---|---|
| 제품 비전 | 개인이 기간(시작일~종료일)이 있는 할일을 카테고리별로 관리하고, 월/주/일 캘린더로 한눈에 보는 웹 앱 |
| 배경 | 도메인 정의서 1장 '문제 정의 요약' 1~3 |
| 목표 사용자 | 학생, 20대~50대 직장인 |
| 플랫폼 | 웹 우선. 모바일은 반응형 웹 UI로만 지원 |
| 프로젝트 조건 | 1인 개발, 2일 내 핵심 기능 완성, 1인 개발 수준 예산 |

## 3. 범위

### 3.1 In-scope

| 구분 | 항목 |
|---|---|
| 릴리스 범위(Must) | UC-01, UC-02, UC-04~09 전체, UC-10 중 월 뷰 (FR-01~10, FR-13) |
| 일정이 허락하면 포함(Should·Could) | UC-03 내 정보 수정, UC-10 중 주·일 뷰, 캘린더에서 편집 이동 (FR-11, FR-12, FR-14~16) |
| 공통 | 반응형 웹 UI(데스크톱·모바일 브라우저) |

| 항목 | 근거 |

## 4. 기능 요구사항

우선순위(MoSCoW): **Must** = 2일 내 반드시 완성(릴리스 기준), **Should** = Day 2 잔여 시간에 완성, **Could** = 여유 시 진행, **Won't** = 이번 범위 아님(3.2). 구분 근거는 P-03.

오류 응답의 상태 코드와 `code` 값은 NFR-15를 따른다. 모든 입력 화면(SCR-01, SCR-02, SCR-04, SCR-06, SCR-07)은 400 `VALIDATION_ERROR`의 `fields` 사유를 해당 입력란 옆에, 그 밖의 오류는 `message`를 폼 상단에 표시한다. 폼이 없는 화면(SCR-03 목록, SCR-05 캘린더)의 오류는 화면 상단에 표시한다. 조회 중·저장 중 화면 상태는 P-22, 화면 경로와 상태 유지는 P-23을 따른다.
