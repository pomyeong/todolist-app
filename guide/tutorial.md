**가장 중요한 원칙 세 가지**

1. **문서가 먼저, 코드는 나중.** 무엇을 바꾸든 위쪽 문서부터 고치고(변경 이력 남김) 코드를 맞춘다.
2. **문서끼리 충돌하면 위쪽 문서가 이긴다.** 도메인 > PRD > 시나리오 > 와이어프레임 > 스타일 가이드 > 구조 원칙 > 아키텍처 > ERD > 실행 계획 > API 명세.
3. **오버엔지니어링 금지.** 몇 줄로 되면 라이브러리를 쓰지 않는다(i18n·화면 모드·CORS 모두 직접 몇십 줄로 구현).

## 2단계. 설계 문서 (11-03 ~ 11-04)

문서마다 **ID 체계**를 정하고, 다른 문서는 ID로만 참조한다(규칙을 두 번 쓰지 않음). 모든 문서 맨 위에 **버전 이력 + 변경 이력(변경 위치·내용·사유·작성자)** 표를 둔다.

### 2-1. 도메인 정의서 `docs/1-domain-definition.md`
- 내용: 목적, 유비쿼터스 언어(용어 사전), 엔티티·속성·관계(mermaid ER), 상태 정의(ST-01~04), 비즈니스 규칙(BR-xx), 유스케이스(UC-xx), 미결 사항.
- 방법: 초안 → "품질 평가 Top 5" 셀프 리뷰 → v0.2 반영. 이후 하위 문서 작성 중 발견한 공백을 계속 역반영(v0.3~).
- 예: 상태는 저장하지 않고 `오늘`과 날짜로 파생(ST), "시작일 ≤ 종료일"(BR-07), "기본 카테고리는 삭제 불가"(BR-12).

### 2-2. PRD `docs/2-PRD.md`
- 입력: 도메인 정의서 + `prompts/PRD.txt`(목표 사용자, 비즈니스 목표, 기술 제약, 일정, 팀, 예산, 접근성 범위).
- 내용: 목표·지표(G), 범위·범위 외, 기능 요구사항(FR, MoSCoW 우선순위, 수용 기준), 화면(SCR), 비기능(NFR), 기술 스택, 마일스톤(M), 리스크(R), **결정 사항(P-xx)**.
- 핵심 습관: 애매한 것은 전부 `P-xx 결정`으로 못 박는다(예: P-04 인증 방식, P-16 캘린더 표시, P-23 라우트).

### 2-3. 사용자 시나리오 `docs/3-user-scenario.md`
- 공통 전제(기준 날짜 2026-11-04, 예시 데이터 T1~T4, 다른 사용자 U2) → SC-01~13(단계별 행동·시스템 반응·화면) → 예외(E-xx: 조건, 응답 코드, 결과) → 추적성 매트릭스(UC→SC, FR→SC).
- 예시 데이터를 고정해 두면 이후 테스트·브라우저 점검이 모두 같은 데이터로 재현된다.

## 7단계. 운영 다듬기 (11-05)

각 요청마다 **문서 → 코드 → 테스트 → 브라우저 확인 → 커밋** 순서를 지켰다.

1. 헬스 체크에 DB 연결 상태(200 `db:up` / 503 `db:down`).
2. Swagger UI를 개발 환경에서만(`/api/docs`, CDN, npm 의존성 없음).
3. Vite 프록시 → CORS(허용 출처 하나, `credentials:'include'`, `SameSite=Lax`이므로 같은 사이트 배치).
4. CORS 출처·토큰 만료(분·일)를 환경변수로(양의 정수 검증, 기본값 유지).
5. 스키마 단일 출처를 `docs/schema.sql`로 이동, `db:init` 경로 변경.
6. 코드 기준으로 문서·API 명세 전체 동기화(쿠키 헤더 실제값, CORS 헤더 등).

## 10. 반복해서 쓴 작업 패턴

**변경 요청 1건 처리 순서**
1. 관련 코드·문서를 읽고 영향 범위를 적는다(호출부, 테스트, 문서 ID).
2. 위쪽 문서부터 고친다 — 내용 + 버전 이력 + 변경 이력, 근거 문서 버전표(swagger) 동기화.
3. 코드 수정. 분기가 있는 로직은 순수 함수로 빼고 단위 테스트.
4. `biome check` → `tsc -b` → 테스트(백엔드 `npm test`, 프론트 `vitest run`).
5. Playwright로 실제 화면 캡처·측정(데스크톱 1280, 모바일 360, 밝은·어두운 모드, 가로 넘침 0).
6. 결과 보고 → 사용자가 "커밋/푸시"라고 할 때만 커밋·푸시.

**실제로 겪은 함정과 해결**

| 함정 | 증상 | 해결 |
|---|---|---|
| Windows CRLF | 문서 치환 스크립트가 0회 일치 | 파일의 줄바꿈을 감지해 패턴의 `\n`을 맞춤 |
| JS `replace`의 `$'` | 정규식 문자열을 넣었더니 명세 뒷부분이 복제됨 | `s.replace(a, () => b)`처럼 함수로 치환 |
| Git Bash에서 curl 한글 본문 | 서버에 깨진 문자열 저장, 409 | 본문을 UTF-8 파일로 쓰고 `--data-binary @file` |
| `git checkout` 후 CRLF | 포매터가 줄바꿈 차이로 오류 | LF로 정규화 |
| 문서 반영 누락 | SCR-05가 옛 결정(반복 표시)으로 남음, swagger 근거 버전표 멈춤 | 기능마다 영향 문서 목록을 먼저 만들고 grep으로 옛 문구 검색 |
| 셸 따옴표 | `node -e` 안 정규식·백틱 깨짐 | 스크립트를 파일로 쓰고 실행 |
| 개발 DB 스키마 변경 | `--reset`은 데이터 삭제 | NULL 허용 컬럼은 `ALTER TABLE ... IF NOT EXISTS`, README에 절차 기록 |
| 위치 지정 겹침 | 선택 테두리를 위로 올리려다 막대가 가려짐 | 내용 요소에도 `position: relative`, 테두리만 `z-index` |

## 11. 정리 산출물 — `guide/`

| 파일 | 용도 |
|---|---|
| `guide/tutorial.md` | 이 문서. 사람이 읽는 진행 기록 |
| `guide/ai-playbook.md` | AI에 한 번에 읽히는 단일 파일. 규칙·절차·템플릿 + **부록 A(부트스트랩 파일 원본 22개)** + **부록 B(재사용 기반 코드 26개)** |
| `guide/playbook-src/` | 플레이북 생성 재료: `head.md`·`body.md`(본문), `claude-template.md`, `PRD.txt`(템플릿), `build.mjs`(생성), `verify.mjs`(부록이 원본과 같은지 검사) |

부록은 실제 파일에서 자동으로 만들어지므로 손으로 고치지 않는다. 원본(스킬·에이전트·설정·기반 코드)을 바꿨다면:

```bash
node guide/playbook-src/build.mjs     # ai-playbook.md 다시 생성
node guide/playbook-src/verify.mjs    # "블록 48개, 원본과 다름 0개"가 나와야 함
```

본문(규칙·절차)을 바꾸려면 `head.md`·`body.md`를 고친 뒤 같은 두 명령을 실행한다.

## 12. 다음 프로젝트 시작하기 (플레이북 사용 절차)

**사람이 하는 일은 ①②③④와 각 게이트의 `다음`뿐이다.** 나머지는 AI가 플레이북대로 한다.

### ① 준비물 설치 (처음 한 번)
Node.js 22+, PostgreSQL 17(슈퍼유저 비밀번호 기억), Git(Windows는 Git Bash 포함), Chrome, Claude Code. 확인 명령은 플레이북 1장.

### ② 새 폴더에 플레이북 복사 → Claude Code 실행
```bash
mkdir budget-app && cd budget-app
mkdir guide && cp <이 저장소>/guide/ai-playbook.md guide/
claude
```

### ③ 부트스트랩 (첫 프롬프트)
```text
@guide/ai-playbook.md 를 읽고 2장 부트스트랩을 실행해줘.
앱 이름: 가계부, 슬러그: budget, PostgreSQL 사용자/비밀번호: postgres / ****
```
AI가 하는 일(플레이북 2.2): 준비물 버전 확인 → 폴더 생성 → 부록 A 파일 22개 생성(이름만 치환) → DB `budget`·`budget_test` 생성 → `.env`·`.env.test`(JWT 비밀키 자동 생성) → `npm install` 두 번 → 확인 → 첫 커밋 → 다음 할 일 안내.
- 이 프로젝트에서 같은 파일들로 시험했을 때 22개 모두 제자리에 생기고 JSON 6개가 정상 파싱됐다.

### ④ Claude Code 재시작 → MCP 승인
종료 후 다시 열면 `.mcp.json` 서버 사용 승인을 묻는다 → 승인. `/mcp`로 context7·playwright·chrome-devtools·postgresql이 connected인지 본다.

### ⑤ 설계 시작
```text
@guide/ai-playbook.md 4장 단계 1부터 진행해줘. 입력 시트는 아래와 같아.
# 제품
- 한 줄 설명: 월별 수입·지출을 기록하고 카테고리별로 보는 가계부
- 핵심 엔티티: 사용자, 거래, 카테고리, 예산
- 핵심 행동: 거래 등록, 월별 조회, 카테고리 합계, 예산 초과 알림
- 범위 외: 은행 연동, 공유 가계부
# 비즈니스
- 목표 사용자: 20~40대 직장인 / 일정: 3일 / 1인
# UX
- 참고 디자인: (캡처 첨부)
```
- AI는 단계(도메인 → PRD → 시나리오 → 와이어프레임 → 구조 원칙 → 아키텍처 → ERD·DDL → 실행 계획 → API 명세 → 스타일 가이드)마다 산출물 요약·가정·질문을 보여주고 멈춘다. 확인 후 `다음`.
- 맡기고 싶으면 `자동 진행` — 질문은 추천안으로 정하고 결정 표에 '가정'으로 남긴다. 나중에 결정 표만 훑어보고 바꿀 것을 말하면 된다.

### ⑥ 구현·검증
```text
실행 계획 순서대로 T-CM·T-DB·T-BE Task를 /develop-backend로 진행해줘
/develop-frontend FE-01 ~ FE-xx 까지 선후행 작업을 고려해서 순서대로 에러없이 작업해줘
T-QA Task(반응형·브라우저, 시나리오 셀프 체크)를 진행해줘
선행 테스크를 고려하여 모든 테스크가 에러없이 개발되었는지 확인하고, 코드 기준으로 docs와 swagger를 현행화해줘
```
- 구현 시작 때 AI는 부록 B 기반 코드(설정·DB·오류·CORS·인증 미들웨어·앱 조립·DB 스크립트·테스트 헬퍼·API 클라이언트·다국어·화면 모드·토큰 CSS 등)를 먼저 놓고 '바꿀 곳'만 고친다. TodoList에서 T-BE-02~07, T-FE-02·04에 해당하던 작업의 대부분이 이것으로 끝난다.
